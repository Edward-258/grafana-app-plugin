# ECS 插件复用 Grafana Alerting——捆绑数据源 + 引导式建规则

## 目标形态（用户视角）
1. 用户在 Grafana Alerting UI 里自己创建规则（插件不做一键建规则、不碰 provisioning API），可自由调节阈值：如「距到期 < N 天」「可用余额 < ¥X」「月账单 > ¥Y」。
2. 前提是插件数据能被规则查询——所以给插件**捆绑一个 datasource**（app+datasource 组合，官方支持），后端把资产/账单快照暴露成数据帧。
3. 插件界面放**告警引导卡**：说明怎么建规则 + 跳转 `/alerting/list` 深链。

## 已核实的技术事实
- Grafana 11.6：Alerting 规则只能查询「已注册且有后端的 datasource 插件」；app 可通过 `includes: [{type:"datasource"}]` 捆绑 ds（twinmaker 先例）；通知复用已有 contact point（labels 路由），无自定义 receiver 扩展点。
- SDK v0.296.4（本地源码核实）：`backend.Manage(pluginID, ...)` 单次只服务一个插件 → **双二进制方案**（`gpx_ecs` + 新增 `gpx_ecs_ds`，两个进程）。
- 双进程意味着 ds 有独立的实例设置 → **凭证同步**：配置页（Admin）保存 AK/SK 时，经 Grafana API 同步写入 ds 的 secureJsonData（实现首验 `PUT /api/plugins/local-ecs-app-ds/settings` 是否收 secureJsonData；不行则 fallback：ds 自带配置页复录一次）。

## 实施步骤

### P1 捆绑 ds 骨架
- `src/datasource/plugin.json`：type=datasource，id=`local-ecs-app-ds`（SSOT 约定 `pkg.name + "-ds"`），`backend:true, alerting:true, executable:"gpx_ecs_ds"`。
- `src/datasource/module.tsx`：最小 ConfigEditor（提示"凭证在 ECS 资产插件配置页管理"）+ 简单 QueryEditor（选帧：account/assets）。
- app 的 `src/plugin.json` 增 `includes` ds 条目（**红线#1**：改后必须浏览器验证扩展菜单仍在，跑 panelMenu e2e）。
- webpack 多配置（ds 独立 entry/publicPath → `dist/datasource/`），CopyWebpackPlugin 复制 ds plugin.json（`%PLUGIN_ID_DS%` 替换，`scripts/gen-permissions.js` 里推导 `pkg.name + "-ds"`，不动权限 SSOT）；build 脚本增 `go build -o dist/gpx_ecs_ds`。
- 验收：构建后 Grafana 识别 ds，能创建 ds 实例，CheckHealth 绿。

### P2 数据面（pkg/ds 新包）
- `QueryDataHandler`：读 settings 凭证 → 复用 `pkg/aliyun` resolver（全地域枚举 + BSS 链路 + SWR 缓存，ds 进程内独立实例）→ 返回两类宽表帧：
  - `account`：availableAmount/couponAmount/billTotal（数值）+ currency/billingCycle（字符串），单行。
  - `assets`：每实例一行：instanceId/name/instanceType/regionId/chargeType/expiredTimestamp/**daysToExpire（后端算好天数，规则直接阈值比较）**/leaseStartTimestamp。PostPaid 到期字段置 null（规则配 noDataState）。
- **红线复检**：帧字段全部来自 PublicAsset 级裁剪，**无任何 IP**；复用/扩展现有守护测试。
- **财务门禁**：有用户上下文（带 X-Grafana-Id）走 authz（ecs:reveal），降级走 org 角色映射（与 auth.go 一致）——Viewer 交互查询拿不到 account 帧；无用户上下文（告警引擎评估态）放行。实测校准 11.6 评估请求的 PluginContext 形态。
- 已知取舍（写入文档）：告警实例的当前值对「能看到告警的人」天然可见（Viewer 默认可读告警列表），财务数字进入告警体系后即具广播属性——这与插件 UI 的 ecs:reveal 门禁并存，不冲突但需明示。

### P3 凭证同步
- 配置页保存成功后（Admin-only 已有门禁），前端经 Grafana API 把 AK/SK 同步写入 ds settings 的 secureJsonData；只发被修改的键、加密存储原则不变（红线#4）。首验 API 行为，失败则 fallback 为 ds 配置页复录。

### P4 引导卡 + 深链
- `src/App.tsx`（账户概览栏旁）新增告警引导卡：建规则步骤、示例（`daysToExpire < N`、`availableAmount < X`）、SWR 缓存 5min → 建议评估间隔 ≥5m、深链按钮跳 `/alerting/list`。卡内余额相关示例仅 ecs:reveal 可见，资产到期部分 ecs:read 即可（与现有分级一致）。

### P5 provisioning / e2e / 文档
- `provisioning/datasources/`：预置 local-ecs-app-ds 实例（固定 uid），引导卡文案直接引用。
- e2e 新增 spec：ds 实例存在、`/api/ds/query` 返回帧、Viewer 对照实例查 account 帧无财务字段；原 6/6 回归必须绿。
- go test（帧门禁 + IP 不出现单测）、golangci-lint、tsc、`npm run build` 全过。
- 文档：README、docs/grafana-plugin-official-spec.md（新增 ds/告警章节）、AGENTS.md（构建产物、双二进制、告警广播属性）、CHANGELOG。

### 收尾验证
compose 重建（新 plugin.json 需重启加载）→ `npm run e2e` 全绿 → 浏览器实建一条「daysToExpire < 大阈值」规则实证 Pending/Firing 流转（无 AK 时降级为帧结构验证）。

## 明确不做
- 不做插件内一键创建规则（不调 provisioning/ruler API）。
- 不做自定义联系人点类型（复用 Grafana 已有 contact point + labels 路由）。
- 不动现有 RBAC 三个 action 与 auth.go 主逻辑（ds 侧复用判定逻辑，权限字符串零新增）。

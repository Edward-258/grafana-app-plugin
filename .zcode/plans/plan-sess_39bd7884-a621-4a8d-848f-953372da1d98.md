# ECS 租期信息采集：CreationTime / ExpiredTime / 计费方式全链路透出

## 口径（已确认）

- **租赁开始 ≈ CreationTime**（实例创建即首次购买起点，续费不更新；不接 BSS 订单 API）
- **DescribeInstances 的 `StartTime` 弃用**——官方语义是"最近一次开机时间"，与租期无关，绝不采用
- **ExpiredTime 仅包年包月（PrePaid）有意义**；按量付费（PostPaid）无到期，显示"按量付费"
- 展示：资产列表加"创建时间/到期时间"两列（插在地域之后），面板弹窗加行；不做到期高亮

## 关键事实：数据已在链路里，只是被丢弃

每 5 分钟的全地域扫描响应中本来就带这三个字段，`parse.go` 的 `rawInstance` 没声明它们而被 `json.Unmarshal` 静默丢弃。resolver/handlers/缓存**零改动**——`Public()` 白名单放行后字段自动流经 enrich/resolve 两个端点，SWR 缓存部署后下一轮扫描自动携带。

## 改动清单（5 个文件）

**后端（3）**

1. `pkg/aliyun/client/parse.go`：`rawInstance` 增加 `CreationTime`/`ExpiredTime`/`InstanceChargeType` 三个 string 字段（json tag 对应 PascalCase），`toInstance()` 原样拷贝（**不解析时间**——`yyyy-MM-ddTHH:mmZ` 分钟精度 UTC 字符串原样透传，解析留给前端，避免后端时区假设）
2. `pkg/aliyun/model/instance.go`：`Instance` 与 `PublicAsset` 加同名字段（json tag：`creationTime`/`expiredTime`/`chargeType`，均 omitempty），`Public()` 白名单拷贝——日期/计费方式非敏感，不触碰 IP 红线
3. 测试：parse 层加一条"原始 JSON → toInstance → 新字段正确解析"的单测（喂含新字段的样例 JSON）；model 层断言 `Public()` 输出包含新字段（顺带确认 `TestPublicAssetOmitsIPs` 守护不受影响）

**前端（2）**

4. `src/EcsInfo.tsx`：`EcsAsset` 加三个可选字段；新增导出 `fmtTime(iso)` 工具——先把无秒的 ISO 归一化（`T15:04Z` → `T15:04:00Z`，兼容 JS Date 解析），再转本地时区显示 `YYYY-MM-DD HH:mm`；`EcsFields` 弹窗加三行：计费方式（PrePaid→包年包月 / PostPaid→按量付费）、创建时间、到期时间（PostPaid 显示"—"）
5. `src/App.tsx`：表头地域后插"创建时间/到期时间"两列；单元格创建时间用 `fmtTime`，到期列 `chargeType === 'PostPaid' ? '按量付费' : fmtTime(expiredTime)`；搜索过滤的 join 串补上两个新字段

## 验证

- `go vet && go test`（含新单测）、`npx tsc --noEmit`、`npm run build`
- 重启后 curl `/ecs/enrich` 与 `/ecs/resolve`：响应出现 `creationTime`/`expiredTime`/`chargeType` 真实值（注意重启清缓存，首个请求付一次全量扫描后字段才出现）
- 无头浏览器看一眼资产页新列与弹窗新行（本次不改 plugin.json，红线不触发，属常规 UI 回归）
- 按量付费实例如有，确认显示"按量付费"而非空到期

## 不做的事（记录在案）

- 不接 BSS 订单 API（真实计费周期起点，将来要精确续费周期时的升级路径）
- 不采集 `StartTime`（开机时间，语义陷阱）
- 不做到期高亮/排序（用户本轮明确不要）
- 不动 AutoReleaseTime（按量付费自动释放时间，需要时再加，一行 tag 的事）

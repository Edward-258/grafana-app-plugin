# RBAC 官方兼容模式：plugin.json 声明式 roles/actions + AK 改写仅 Admin

## 官方兼容点（相对上一版的变化）

1. **`plugin.json` `roles[]` 声明三个自定义 action**（官方 11.6 RBAC 模式，OSS 可用，`grants` 自动授予内置角色）——权限语义从"代码里比角色字符串"变成"官方声明 + action 校验"。
2. **`includes[]` 用官方 `action` 字段**替代 `role` 做页面/导航门禁。
3. **前端用官方 `hasPermission()`**（`@grafana/runtime`）门禁 UI，不再读 bootData 角色字段。
4. **后端按官方 authz 模式**：`externalServiceAccounts` toggle + `grafana/authlib/authz` client，通过 `X-Grafana-Id` 校验 action（官方 implement-rbac-in-app-plugins 指南同款代码）；无 id token 时（匿名/服务端发起）回退到 `PluginContext.User.Role` 映射，保证 dev 匿名 Admin 流程不中断。
5. AK ID 仍迁入 `secureJsonData`（脱敏强制力的前提，与上版一致）。

## 权限矩阵（三 action）

| action | 授予（grants） | Viewer | Editor | Admin |
|---|---|---|---|---|
| `local-ecs-app.ecs:read` — 资产对齐 + 脱敏 AK | Viewer, Editor, Admin | ✅ | ✅ | ✅ |
| `local-ecs-app.ecs:reveal` — 展开完整 AK ID + 连通测试 | Editor, Admin | ❌ | ✅ | ✅ |
| `local-ecs-app.ecs:write` — **改写 AK ID / Secret** | **仅 Admin** | ❌ | ❌ | ✅ |

端点映射：`/ecs/enrich|resolve`→read；`/ecs/ak`→read（响应含 `full` 仅当 reveal 通过）；`/ecs/test`→reveal；`/health` 不设防。

## 具体改动

**`src/plugin.json`**：
- 新增 `roles[]`（上表三个角色，名称如「ECS 资产查看 / AccessKey 查看 / AccessKey 管理」）+ `iam` 段（`users.permissions:read`, scope `users:*`，供 authz client 查询用户权限）。
- root page include 加 `action: local-ecs-app.ecs:read`；「配置」include 的 `role: "Admin"` 改为 `action: local-ecs-app.ecs:write`。
- `grafanaDependency` 升为 `>=11.6.0`（官方 RBAC 指南的版本要求，我们实测版本也是 11.6.0）。

**`docker-compose.yaml`**：新增 `GF_FEATURE_TOGGLES_ENABLE: externalServiceAccounts`。

**后端 `pkg/app/handler/`**：
- `go get github.com/grafana/authlib/authz`（连带 cache 依赖，go mod tidy）。
- 新增 `auth.go`：按官方指南实现 `GetAuthZClient`（token 来自 `GrafanaConfigFromContext`，`WithSearchByPrefix("local-ecs-app")`，本地缓存、按 token 复用）+ `requireAction(action, next)` 中间件：有 `X-Grafana-Id` → `HasAccess(token, action)`；无 → 按 `User.Role` 映射（Admin=全部，Editor=read+reveal，Viewer=read；User nil → 403）。
- `plugin.go` 路由按上表包中间件；新增 `GET /ecs/ak`（脱敏 `前3…后3`，短值更严；reveal 通过才带 `full`；`legacy` 标记旧 jsonData 副本）。
- `settings.go`：AK ID 读取改 secure 优先、jsonData 兜底（旧部署无缝）。

**前端 `src/ConfigPage.tsx`**：
- AK ID 已配置时显示脱敏值 + 眼睛按钮（仅当 `/ecs/ak` 返回 `full`，即 Editor/Admin）；
- 「更换」输入框、AccessKey Secret 编辑、保存按钮：仅 `hasPermission('local-ecs-app.ecs:write')`（Admin）可见；
- 测试按钮仅 `hasPermission('local-ecs-app.ecs:reveal')`；
- 保存时 AK ID 改存 `secureJsonData`、只发被修改的键；`legacy` 时提示重保存迁移。
- `App.tsx`/`prom.ts`/`EcsInfo.tsx` 不动。

## 测试与验证

- Go 单测：`requireAction` 回退路径（nil/Viewer/Editor/Admin × 三个 action）、`/ecs/ak` 脱敏与 full 下发、`configFrom` 双读。
- `go vet ./... && go test ./...`、`npx tsc --noEmit`、`npm run build`、compose 重启。
- **plugin.json 改了 → 按红线必须无头浏览器回归**：配置 tab 脱敏+眼睛（匿名 Admin）、面板菜单扩展仍在、资产页正常。
- 临时 `GF_AUTH_ANONYMOUS_ORG_ROLE: Viewer` 的 compose override + curl：`/ecs/ak` 只回 masked、`/ecs/test` 403——回退路径的真凭据。
- 重启后确认 Grafana 日志无 roles 注册报错（roles 注册失败会在 server 日志输出）。

## 风险与说明

- `externalServiceAccounts` 仅支持单 org——我们本就单 org（org_id 1）✅。
- dev 匿名 Admin 无 id token 时走角色回退路径，行为与官方 authz 一致（Admin 全通过）。
- `grafanaDependency` 升到 11.6 意味着放弃 11.1–11.5 兼容（官方 RBAC 指南本身要求 11.6+）。
- 部署后 Admin 重保存一次完成 AK ID 迁移到加密存储（此前旧 jsonData 副本仍对登录用户可见）。
- 实施后同步更新 `AGENTS.md`（红线 #4 + 权限矩阵）与 `docs/grafana-plugin-official-spec.md` §8。
